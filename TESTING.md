# Testing

## Backend — xUnit v3 (`cms-api/cms-api.Tests`)

```bash
cd cms-api
dotnet test
```

Two kinds of test live side by side:

- **`Unit/`** — the pure logic (`Slug`, `ContentItemValidator`, `ContentSchema`, `JwtOptions`,
  `JwtTokenService`) plus the two services that need a database (`ReferenceValidator`,
  `ReferenceFinder`). The database-backed ones run against real SQLite held in memory, not
  the in-memory provider, so a query that could not be translated fails here too.
- **`Integration/`** — the whole application in-process through `WebApplicationFactory`.
  Only the database (a private in-memory SQLite) and the upload directory (a temp folder)
  are substituted; the JWT pipeline, the authenticated-by-default fallback policy, model
  binding, the migrations and the admin seeding all run as they do in production.

`CmsApiFactory` supplies configuration through environment variables rather than
`ConfigureAppConfiguration`, because `Program.cs` reads and validates the `Jwt` section
while the builder is still being configured — before any callback the factory could
register would run.

## Frontend — Vitest + Testing Library + MSW (`cms-frontend`)

```bash
cd cms-frontend
npm test              # one run
npm run test:watch    # re-runs on change
npm run test:coverage # v8 coverage report
```

The API is faked at the network layer with MSW rather than by stubbing `fetch`, so
`src/lib/api.ts` does its real request building, status handling and error parsing.
Any request a test did not mock fails that test instead of silently 500-ing.

Each test declares the responses it needs with `server.use(...)`; there are no shared
default handlers. `src/test/auth.ts` mints decodable (unsigned) JWTs for signing a test in.

## Swagger

With the API running in Development:

- UI — <http://localhost:5051/swagger>
- Document — <http://localhost:5051/openapi/v1.json>

The document is generated by `Microsoft.AspNetCore.OpenApi`; Swashbuckle only renders it.
Operation summaries come from the XML doc comments already on the controllers, and the
transformers in `cms-api/OpenApi/` mark each operation with the security it actually
requires — so the anonymous read endpoints the public site depends on are not documented
as needing a token. Press **Authorize** and paste a token from `POST /api/auth/login` to
call the protected endpoints from the docs page.
